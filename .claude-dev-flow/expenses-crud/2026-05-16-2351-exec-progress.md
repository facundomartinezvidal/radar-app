## Schema decisions

### `profiles`
- 1:1 `auth.users(id)`, on-delete cascade
- columns: `id uuid pk`, `display_name text`, `avatar_url text`, `created_at`, `updated_at`
- trigger on `auth.users` insert → create profile row
- RLS: user can read/update own row only

### `categories`
- global lookup (not per-user): `id uuid`, `slug text unique`, `name text`, `icon text` (lucide name), `color text` (hex), `sort_order int`
- seed: comida, supermercado, transporte, ocio, salud, hogar, servicios, viajes, otro
- RLS: SELECT for any authenticated user; INSERT/UPDATE/DELETE service_role only

### `expenses`
- columns:
  - `id uuid pk default gen_random_uuid()`
  - `user_id uuid not null` → fk `auth.users(id)` on delete cascade
  - `amount numeric(14,2) not null` (positive)
  - `currency text not null check in ('ARS','USD')`
  - `category_id uuid` → fk `categories(id)` on delete set null
  - `description text` (≤ 240 chars)
  - `occurred_at timestamptz not null default now()`
  - `created_at timestamptz not null default now()`
  - `updated_at timestamptz not null default now()`
- trigger: `updated_at = now()` on update
- indexes: `(user_id, occurred_at DESC)`, `(category_id)`, `(currency)`
- RLS: user can CRUD only rows where `auth.uid() = user_id`

## Notes
- ARS = pesos · USD = dólares · FX out of scope (Phase 9+ TBD)
- "Income vs expense" out of scope this phase — only expenses (negative cash). Income flow later.
- Trigram search on `description` deferred (post-MVP). Use `ilike` for v1.
