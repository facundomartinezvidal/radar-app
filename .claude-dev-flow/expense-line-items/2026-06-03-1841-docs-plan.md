## Key facts extracted from source

### Schema
- Table: `expense_items` with id, expense_id, user_id, name, quantity (numeric 14,3), unit_price (nullable), line_total (required), position, timestamps
- RLS: owner-only 4 policies, `(select auth.uid()) = user_id` pattern (cached subquery)
- RPCs: `create_expense_with_items` + `update_expense_with_items`, both `security invoker`, `set search_path = ''`
- Update strategy: delete-all + reinsert (ids rotate on each update)
- Cascade delete from expenses → items

### OCR integration
- Edge fn returns `items: OcrItem[]` with camelCase fields (name, quantity, unitPrice, lineTotal)
- `normaliseItems()` in edge fn drops nameless items, caps at 50
- `mapOcrItems()` in lib/ocr.ts: drop empty names, qty default 1, lineTotal fallback chain
- Client schema: `ocrItemSchema` with `.catch()` defensive parsing

### Form
- `ExpenseItemsField` component using `useFieldArray`
- Collapses/expands, auto-expands if items present
- qty × unit_price → recomputes line_total (manual edit of line_total wins until next qty/price change)
- Mismatch warning: `|Σ items - amount| > 0.5`, amber, non-blocking
- Cap 50 items

### Write path
- Create: always uses `create_expense_with_items` RPC
- Update with items: `update_expense_with_items` RPC
- Update without items (`items === undefined`): direct column update, items untouched
- Read: `'*, category:categories(*), items:expense_items(*)'` select, client-side sort by position

- 4 files total: 2 baseline + 2 new HU-18 migrations
