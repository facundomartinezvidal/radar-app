# Edge Cases: Items detallados (HU-18)

Date: 2026-06-03

## OCR / Edge Function

### Ticket sin detalle de renglones
- **Trigger**: ticket térmico borroso, factura sólo con total
- **Expected**: `items: []`, flujo actual intacto, form con sección Detalle vacía
- **Priority**: P0

### Payload off-spec de Groq (items no-array, campos basura)
- **Trigger**: modelo devuelve JSON con `items` como string/objeto
- **Expected**: `normaliseItems` (edge) descarta; cliente `z.array(...).catch([])` → `[]`
- **Priority**: P0

### Item sin nombre o nombre vacío post-trim
- **Trigger**: renglón ilegible, OCR alucina campo
- **Expected**: drop silencioso del item (edge + `mapOcrToPrefill`)
- **Priority**: P0

### Más de 50 items
- **Trigger**: ticket mayorista largo
- **Expected**: cap `MAX_ITEMS = 50` en edge; zod `max(50)` en form
- **Priority**: P1

### lineTotal null pero qty + unitPrice presentes
- **Expected**: computar `round2(qty × unitPrice)` en normalización
- **Priority**: P1

### lineTotal null y sin qty/unitPrice utilizables
- **Expected**: item se mantiene con `line_total: 0` en prefill — usuario corrige; contribuye 0 a la suma y dispara warning mismatch
- **Priority**: P1

### Cantidades por peso (0.750 kg)
- **Expected**: `quantity numeric(14,3)`, decimal en form; qty×unit_price ≠ total impreso por redondeo → manual gana
- **Priority**: P1

### Valores negativos (descuentos como renglón)
- **Trigger**: ticket con renglón "DESCUENTO -500"
- **Expected**: coerción rechaza negativos → null/drop; el descuento se refleja como mismatch (warning explica "descuentos o propinas")
- **Priority**: P2 — documentado, no soportamos renglones negativos en v1

### Latencia agregada por items
- **Expected**: cap 50 + temp 0 mantiene < 20s timeout existente; sin cambio de timeout
- **Priority**: P2

## Form / UI

### Usuario borra todos los items
- **Expected**: gasto se guarda sin items (array vacío → omitido); válido
- **Priority**: P0

### Edición qty/unit_price vs line_total manual
- **Expected**: editar qty o unit_price recalcula line_total; editar line_total directo NO se sobreescribe hasta próxima edición de qty/price
- **Priority**: P1

### Mismatch suma vs total
- **Expected**: `|Σ − amount| > 0.5` → aviso amber, submit habilitado. Sin items → sin aviso
- **Priority**: P0

### Item agregado con campos default y submit inmediato
- **Expected**: zod bloquea: `name` min 1 → "Ingresá un nombre."
- **Priority**: P0

### unit_price vacío (null)
- **Expected**: válido — line_total manda; input vacío ≠ 0
- **Priority**: P1

### Teclado tapa filas de items en tickets largos
- **Expected**: form ya en scroll del screen padre; verificar manualmente en device
- **Priority**: P2

## Persistencia

### Falla parcial insert (constraint violation en item N)
- **Expected**: RPC transaccional revierte expense + items; cliente muestra error genérico de guardado
- **Priority**: P0

### Update sin tocar items
- **Expected**: `input.items === undefined` → path actual de update de columnas, items intactos
- **Priority**: P0

### Update con items (incluye vaciar)
- **Expected**: delete-all + reinsert en transacción; `items: []` explícito borra todos
- **Priority**: P0

### Delete del gasto
- **Expected**: `on delete cascade` borra items
- **Priority**: P0

### RLS cross-user
- **Trigger**: user A intenta leer/insertar items con expense_id de user B
- **Expected**: select vacío; insert rechazado (policy `user_id = auth.uid()`); RPC inserta `user_id` desde `auth.uid()` — no confiable desde cliente
- **Priority**: P0

### Concurrencia: dos updates simultáneos del mismo gasto
- **Expected**: last-write-wins (delete+reinsert); aceptable single-user v1
- **Priority**: P2

### Gastos existentes (pre-feature)
- **Expected**: select anidado devuelve `items: []`; cero migración de datos
- **Priority**: P0

### numeric → JS number round-trip
- **Expected**: mismos límites que `amount` actual (max 1e9 en zod); tabular-nums + `formatMoney` para display
- **Priority**: P1
