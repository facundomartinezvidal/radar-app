## Issues Encountered and Resolved

### 1. Jest 30 + React Native 0.81 incompatibility
`jest@30` was initially installed. At runtime, `jest-runtime@30` calls
`this._moduleMocker.clearMocksOnScope()` but the `moduleMocker` injected by the RN
environment came from `jest-mock@29` (bundled by `react-native@0.81`) which lacks that
method. **Fix:** downgraded to `jest@29` + `@types/jest@29` which aligns with
`react-native@0.81`'s peer expectation.

### 2. transformIgnorePatterns not covering pnpm virtual store
The default pattern `node_modules/(?!...)` without a leading `/` or `.pnpm` allowance
caused `react-native/jest/setup.js` (which uses ESM `import`) to not be transformed.
**Fix:** added `/` prefix to anchor the pattern and added `.pnpm` to the allowlist.

### 3. RNTL extend-expect import path
`@testing-library/react-native/extend-expect` does not exist as a root-level entry in
v13. The `matchers.js` root entry exports matchers without calling `expect.extend()`.
**Fix:** used `@testing-library/jest-native/extend-expect` (still installed) which works
correctly and calls `expect.extend()`.

### 4. TypeScript strict: `global` is unknown
With `lib: ["DOM", "ESNext"]` (no `@types/node`), `global` is not a known identifier.
**Fix:** replaced `global.fetch` with `(globalThis as {...}).fetch` which is ESNext-native.
