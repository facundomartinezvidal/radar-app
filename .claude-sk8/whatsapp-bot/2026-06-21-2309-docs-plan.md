## Key facts confirmed from code

### Tables
- `whatsapp_links`: user_id, wa_number, status('linked'|'unlinked'), linked_at, unlinked_at — partial unique on (wa_number) WHERE status='linked', (user_id) WHERE status='linked'; RLS: owner SELECT+UPDATE
- `whatsapp_link_codes`: user_id, code UNIQUE, expires_at, consumed_at; partial unique on (code) WHERE consumed_at IS NULL; RLS: owner SELECT+INSERT
- `whatsapp_messages`: provider_message_id UNIQUE, wa_number, user_id (nullable), direction, body, num_media, status, intent, received_at, processed_at; RLS enabled ZERO policies (service-role only)
- `whatsapp_conversations`: pk=user_id, wa_number, pending_action jsonb, pending_kind, expires_at; RLS enabled ZERO policies (service-role only)

### RPCs
INVOKER (authenticated can call):
- `create_link_code()` → jsonb {code, expires_at}; 10-min expiry; invalidates prior unconsumed codes; 6-char base32 alphabet (no 0/O/1/I/L)

Pattern 1 (REVOKE FROM anon, public, authenticated; service-role only):
- `redeem_link_code(text, text)` → jsonb {status, user_id}; outcomes: linked/expired/reused/invalid/already_linked
- `resolve_wa_user(text)` → uuid | null; E.164 normalize, lookup active link
- `unlink_wa(uuid)` → void; sets status='unlinked'
- `import_transactions_for(uuid, jsonb)` → int; clone of import_transactions with p_user_id
- `get_personal_totals_for(uuid, timestamptz, timestamptz)` → table(currency, total, count)
- `get_expense_by_category_for(uuid, text, timestamptz, timestamptz)` → table(category rows)
- `get_expense_by_period_for(uuid, text, text, timestamptz, timestamptz)` → table(bucket, total, count)
- `get_income_by_period_for(uuid, text, text, timestamptz, timestamptz)` → table(bucket, total, count)

### Webhook modules
- `index.ts` — router: OPTIONS/GET/POST; reads raw body before JSON parse for HMAC
- `verify.ts` — checkHandshake, verifySignature (pure, unit-testable)
- `graph.ts` — sendText, fetchMediaBytes (Meta Graph API v21.0)
- `db.ts` — service-role helpers: recordInbound, resolveUser, redeemLinkCode, getConversation, setPendingAction, clearPending, markProcessed, unlinkUser, countRecentInbound
- `dispatch.ts` — handleMessage: idempotency → rate-limit → type guard → identity → media branch → audio transcribe → classify → state machine
- `classify.ts` — classifyIntent via Groq llama-4-scout-17b; 9 intents; never throws (fallback)
- `capture.ts` — handleCapture (text), handleConfirm, handleMediaCapture; calls extract-document with service-role Bearer
- `transcribe.ts` — Groq Whisper whisper-large-v3; multipart formdata
- `queries.ts` — handleQuery, resolvePeriod (UTC), formatAmount (Argentine locale)
- `recommendations.ts` — handleRecommendation, buildInsightsPayload; calls generate-insights

### App screen
- `app/(protected)/profile/whatsapp.tsx` — linked/unlinked states, generate/copy code, wa.me deep link, two-step unlink confirmation
- hooks: useWhatsappLink, useCreateLinkCode, useUnlinkWhatsapp
- repo: lib/repositories/whatsapp.ts; schema: lib/schemas/whatsapp.ts

### Key design decisions
- D1: DEFINER _for RPCs (p_user_id) not raw service-role inserts — reuse validated business rules
- D2: single webhook router + server-to-server calls to extract-document/generate-insights
- D3: ack 200 fast, async handle via EdgeRuntime.waitUntil
- D4: whatsapp_conversations confirmation state machine (SELECT FOR UPDATE)
- D5: idempotency via whatsapp_messages.provider_message_id UNIQUE

### Spec vs implementation discrepancies to flag
1. feature-def.md acceptance criteria references "Invalid Twilio signature → 403" — provider is Meta, not Twilio. The implementation correctly uses X-Hub-Signature-256 (Meta). This is a copy-paste artifact in the feature-def.md only; all code and specs are correct.
2. tasks.md check "`accept_language` for multilingual queries" is not in the implementation — the intent classifier handles language detection internally but there is no per-user language setting. Minor gap.
3. The `import_transactions_for` migration comment says "Applied to remote: 20260622010000" but the filename is 20260622010559 — minor timestamp mismatch in comment.
